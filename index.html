How it works

A safety-first pipeline.

Every command passes through six stages before a single file moves. Each stage has one job.

1
LLM Interpreter
Plain English → structured JSON command. Gemini is called with a few-shot prompt and forced JSON output mode. The response is never trusted as code — only as data.
interpreter/llm_client.py
2
Schema Validator
Checks the JSON structure against a strict schema contract — allowed actions, required fields. Rejects anything malformed before it reaches the filesystem.
schema/command_schema.py
3
Path Resolver
Translates "downloads" and "desktop" into real Windows paths. OneDrive-aware: checks per-folder existence rather than assuming a single directory layout.
resolver/path_resolver.py
4
Semantic Validator
Does the source file exist? Is the destination safe? Could this be a path traversal? Returns structured error codes, not formatted strings — the presentation layer owns the messages.
validator/validator.py
5
Confirmation Gate
Shows the exact resolved paths before touching anything. For batch operations, re-validates after confirmation — if even one file disappeared, the entire batch is aborted.
main.py
6
Execution Engine
Performs the filesystem operation using shutil and os. Returns status codes only. Every operation is logged with a timestamp.
executor/executor.py

Engineering decisions

Designed, not just built.

Key architectural choices and the reasoning behind them — documented in the repo as Architecture Decision Records.

ADR-001
Provider-agnostic LLM layer
Abstract base class with NotImplementedError. Switching from Gemini to Claude API or any other LLM means adding one class — nothing else changes.
ADR-002
Separate path resolution from validation
Path resolver is a pure translation layer. Validator is a safety layer. Single Responsibility Principle: each module does one job.
ADR-003
Structured error codes
Executors return SOURCE_NOT_FOUND, PERMISSION_DENIED, SAME_PATH. The presentation layer owns all user-facing messages. Logic and display are never coupled.
ADR-004
LLM describes intent, Python discovers files
For organize_folder, the LLM returns only the source path. Python's discover_files() does the actual filesystem scan. The LLM never guesses filenames.
ADR-005
Post-confirmation re-validation
After the user confirms, validate_plan() re-checks every source file. One stale file aborts the entire batch. Confirmation applies to the exact plan shown.
ADR-011
System prompt as architecture
The SYSTEM_PROMPT is a checklist: adding a new action requires updating the prompt before updating any other file. Documented as an architectural invariant.
